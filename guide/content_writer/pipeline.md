# Content Writer — Pipeline 상세

## 소제목 형식 규약

| 수준 | 형식 | 예시 |
|------|------|------|
| 최상위 섹션 | `## N. 섹션명` (점 방식) | `## 1. 이런 상황에서 막힌다` |
| 하위 섹션 | `### N.M 소제목` | `### 2.1 한 줄 정의` |

괄호(`)`) 방식은 사용하지 않는다.

## 카테고리별 아웃라인 구조

### 기본 (6섹션 고정)

```
1) 왜 지금 이 주제인가
2) 핵심 개념을 3분만에
3) 실전 적용 흐름
4) 운영 팁: 실패를 전제로 설계하기
5) 체크리스트 (keywords에서 추출)
6) 마무리: 오늘 바로 할 수 있는 1가지
```

### 개발/AI (dev_ai)

```
1) 이런 상황에서 막힌다 (문제 정의)
2) 핵심 해결 구조 (개념 + 코드)
3) 초심자 함정 3가지
4) 체크리스트 (바로 적용 가능)
```

### 맛집 (food)

```
1) 한줄 결론: 여기 갈 만한가?
2) 근거: 맛 / 분위기 / 가성비
3) 추천 조합: 이렇게 주문하세요
4) 주의사항: 웨이팅·주차·브레이크타임
```

### 여행 (travel)

```
1) 추천 동선 (시간순)
2) 현지 팁 (교통/예약/꿀팁)
3) 비용 정리 (항목별)
4) 추천 루트: 반일 코스 vs 종일 코스
```

## SEO 최적화 로직

### 제목 최적화 예시

| 원본 | SEO 최적화 |
|------|-----------|
| Google Antigravity 소개 | Google Antigravity란? AI 블로그 자동화 구조 정리 |
| vLLM 사용법 | vLLM vs Ollama 비교: 실전 배포 환경에서의 선택 기준 |

### 태그 생성 로직

1. `primary_keywords`에서 추출
2. `secondary_keywords`에서 추출
3. 범용 태그 추가: `["자동화", "블로그운영", "에이전트", "워크플로우"]` (개발/AI의 경우)
4. 중복 제거 → 최대 10개

## 카테고리별 권장 이미지 배치

| 카테고리 | 권장 개수 | 권장 위치 |
|----------|-----------|-----------|
| 개발/AI | 2~3개 | 섹션 2 뒤(코드 흐름/스크린샷), 섹션 3 뒤(에러 화면), 마지막 섹션 앞(결과 화면) |
| 맛집 | 3~4개 | 섹션 1 뒤(대표 음식), 섹션 2 뒤(분위기), 섹션 3 뒤(추천 메뉴), 마지막(외관) |
| 여행 | 4~5개 | 섹션 1 뒤(대표 장소), 동선 주요 스팟마다, 마지막(전망/분위기) |

## photos 파라미터 처리

- `photos` 있으면: 각 파일을 image_plan의 `path`에 채움, slug는 `photo_1`, `photo_2` 등 자동 부여
- `photos` 없고 `photo_set` 있으면: `images/[profile]/[photo_set]/`에서 미사용 사진을 선택해 image_plan의 `path`에 채움
- `photos`, `photo_set` 모두 없으면: topic/keywords를 slug화해 `images/[profile]/[slug]/` 폴더를 자동 매칭
- 매칭 사진이 없으면: image_plan 항목 생성하되 `path`는 `""` 로 남김

## photo_set 폴더 규칙

- 맛집: `images/food/[photo_set]/`
- 여행: `images/travel/[photo_set]/`
- 사용 예: `photo_set: osaka` → `images/travel/osaka/`
- 사용된 사진은 발행 성공 후 `outputs/analytics/photo_usage.json`에 기록되며 다음 글에서 재사용하지 않음
